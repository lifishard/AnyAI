# AnyAI 自适应上下文与长任务管理计划书

状态：执行中。制定日期：2026-09-13。目标版本：1.2.0。

本计划保存本次升级前多轮讨论的结论，供后续实施、验收与继续开发使用。施工进度见 [施工路线图](ADAPTIVE_CONTEXT_ROADMAP.md)。它是实现约束，不因聊天窗口压缩而失效。

## 1. 用户问题与本轮目标

用户最初在日历导出任务中遇到：文件已输出，但模型仍在限流等待；旧版本曾把图片 Base64 错计成文本而误报 27 万 token。1.1.1 已修正图片估算，并加入执行记录、恢复、真实文件卡片和引用/注释。本轮处理更深的架构问题：让任务能跨多轮、压缩、限流和重启连续推进。

用户确认的方向：

- 按需要创建 milestones，达成后划掉，类似桌面 Agent 的 progress；不是每个简单问题都创建计划。
- 优先解决上下文自适应与多策略组合，避免每轮重发大量历史和工具输出。
- 同时适配不同端点、模型、窗口及 reasoning effort；不能只让单个模型的一档设置表现正常。
- 右下角圆圈显示上下文占用，256K 和 1M 路由分别使用自己的窗口；未知上限必须诚实显示。
- 保存本次讨论与实施路线，按顺序执行和验证。
- 本轮保留可观测记录与评测接口；下一轮才考虑 RSI 自动提案、实验、采用与回滚闭环。

成功标准是任务结果完整、约束未丢失、恢复后不重复已完成操作，且整项任务的 token、耗时和被迫中断减少。单次请求更短、里程碑全被勾选或模型说“完成”都不是充分证据。

## 2. 已确认的设计原则

1. 上下文窗口、每分钟额度、累计任务预算分开管理。429 可能来自 RPM、TPM 或账户额度，不能一律归因于上下文过长。
2. “兼容 API Key”不代表所有原生协议和专有功能相同。本轮在现有 OpenAI-compatible Chat Completions 通路上完成自适应基础；供应商原生 Responses/Messages/Gemini 协议与专有压缩是明确的扩展边界，不能假装已支持或将其参数盲发给兼容网关。
3. 不能按模型名猜出确定窗口；模型名中的 256K/1M 也不能覆盖实际路由限制。采用已验证元数据、用户配置、响应头或明确错误中的数字，保存来源、时间和置信状态。
4. 未知额度采用保守调度，依据正常执行被动校准，不以大量收费请求或主动超限探测来找极限。
5. 每个端点/模型有能力档案；共享账户/项目/网关池有独立额度档案；不同思考档位有独立用量估算，但不能凭档位创建虚假的额外额度。
6. 输入、工具定义、图片、文本附件都计入真实出站请求估算。输出预算必须包含端点要求计入的思考部分，且不能重复计算。
7. 保留用户选定的模型与思考意图。遇到参数不支持应说明；不静默切换模型、不偷偷降低强度、不把未知能力标为已验证。
8. 完整聊天、原始工具结果、用户约束和文件路径持续保存。压缩改变下一轮的工作视图，不删除原始记录。
9. 精确数据由程序保存：任务/里程碑 ID、文件路径、工具调用、完成证据、时间和版本不能靠反复自由摘要维持。
10. 用模型总结只是策略之一；先减少无关输入与旧工具全文，再按需生成结构化增量摘要。摘要要可追溯、可验证、可回退。
11. 压缩模型默认沿用当前已选路由；不能自动把资料发送给另一家服务。压缩调用也计入用量与限流，并使用相同取消机制。
12. 上游签名、工具调用/返回配对、流式完成标记必须按协议处理；不得为了裁剪破坏结构，或执行尚未完整接收的工具参数。
13. 自动恢复在用户配置的预算内进行；用户停止、权限拒绝及不确定的副作用不能被自动重试绕过。
14. 适应模型容量不等于各模型能力相同，也不能承诺零 429、无限任务或供应商故障时仍继续调用。

## 3. 数据与执行结构

执行链：任务状态 → 选择相关材料/压缩 → 组装请求并估算 → 校验端点能力 → 共享额度队列 → 模型/工具 → 保存证据与里程碑 → 下一轮或验收完成。

### 路由能力与额度

- 路由标识包含端点、模型和配置版本，避免修改 base URL 后误用旧数据。
- 能力记录包含总窗口、输出上限、思考字段约束、来源、时间以及估算修正系数。
- 额度支持 RPM、总 TPM、输入 TPM、输出 TPM；允许显式设置共享组。默认同一配置使用保守共享队列，未知账户关系不能凭不同 Key 假定额度互不影响。
- 使用供应商响应头的 limit/remaining/reset/Retry-After；没有这些信息时，保留“未知”，动态增大发送间隔并在稳定成功后缓慢恢复。
- 来源冲突时采用可确认上限中的较小值，用户填写的更低预算作为硬约束；弱推断不能覆盖已确认数字。实时响应中的额度与恢复时间优先于旧估计，陈旧观察失效后重新标为未知。明确显示“用户配置”与“服务端确认”的区别。
- 请求预留用于发送前检查；响应 usage 用于结算。明确未生成内容的拒绝不能算作已实际生成一整份输出，但请求仍可能占服务端限流额度。

### 任务状态

- Milestone：稳定 ID、标题、状态（待办/进行中/完成/受阻）、可选验收说明、证据步骤 ID。
- 已完成工具步骤、已验证文件和用户指令独立于摘要保存。
- 完成里程碑需关联真实成功步骤；纯解释类完成可用明确的回答交付说明，不能虚构工具证据。
- 仍有待办/受阻里程碑时，正常 stop 不直接等于任务完成。应在预算内继续，或解释阻碍并保留可恢复状态。
- 里程碑更新支持修改、追加和重新打开；不能通过删除未完成项无声“完成”任务。
- 保留既有副作用日志：派发前保存 intent，成功后保存 result。崩溃后未有可靠结果的修改操作先核实，无法核实则显示“结果未知”，让用户选择核实后跳过或重试；不得当作未执行而自动再写一次。

### 累计预算与阶段

沿用现有默认阶段上限：300,000 token、60 分钟和配置的工具轮次；恢复等待默认最多 15 分钟。摘要与普通模型调用共同消耗阶段预算，所有实际 usage 累计进整个任务记录；无 usage 的已生成响应保守估算，明确拒绝且未产生内容的请求不凭预留值记为实际消耗。限流的请求计数与费用/阶段 token 分开，不假定失败请求不占服务端额度。

自动压缩、退避与正常工具往返不重置阶段预算。预算耗尽时保存未完成项并暂停；用户明确点击“接着跑”开启新阶段，历史总用量保持不变。重启不会清零历史账或自动派发未知副作用。0 仍表示该项不限制；本轮不引入没有价目来源的金额预算。

### 压缩状态

- 每次记录压缩前后估算、策略、来源消息范围、保留边界、摘要版本、用量和校验结果。
- 原始工作记录保留；摘要保存事实、决定、未解决问题、下一步和来源 ID。
- 新摘要先完成结构/引用/关键字段校验，再原子替换有效摘要；失败时保留原摘要与原文，使用本地裁剪或稍后重试。
- 保存近期完整工具批次，不在未完成工具批次中途裁剪。

## 4. 多策略组合

1. 入场控制：窄查询、分页、限制工具输出、按需读取完整落盘结果。
2. 本地处理：去重与折叠旧工具全文，保留结果摘要、状态、原文引用和最近完整批次。
3. 结构化任务记忆：程序保存目标、用户约束、里程碑和文件索引；精确标识符不交给自由摘要改写。
4. 语义压缩：在预测下一轮超出有效工作预算时，对已完成的旧历史生成带来源 ID 的结构化摘要；保留当前用户目标与近期工作。
5. 按需恢复：模型可读取具体原始消息或工具结果，避免摘要遗漏迫使整个任务重新开始。

触发依据为当前工作预算、输出/思考预留、估算误差、下一批工具空间和阶段边界，不将“70%”当作所有模型的固定真理。不能因为这一分钟余额为零就把任务上下文压到零；短时余额不足应等待。

## 5. 用户界面

- 回答区域展示可折叠进度清单；完成项划掉，有证据可追溯；等待额度、整理上下文、暂停与完成有不同状态。
- 输入框右侧显示上下文圆圈。分母为已确认的路由窗口，分子为本轮准备发送的上下文估算；未知窗口显示“待确认”，不伪造百分比。
- 展开显示系统/工具定义/聊天/附件与工具结果的估算、输出与思考预留、工作预算、窗口来源、压缩次数与最近变化。
- 模型窗口和工作预算分开显示。1M 窗口可能采用较小工作预算，用户可以看到开始整理的原因。
- RPM/TPM、等待时间另列，避免把分钟额度与上下文容量混为一谈。
- 切模型、思考档位或输入变化时重新计算；估算标“约”，上游 usage 作为校准数据而非混成同一个测量。

## 7. 本轮与 RSI 的边界

本轮记录执行版本、模型/思考设置、摘要效果、用户纠错所指向的消息与步骤，提供可用于回归的证据。保留原有注释和项目记忆，不把全部注释擅自升级为系统规则。

下一轮才实现“失败 → 原因判断 → 修改候选 → 原案例重放 → 留出案例回归 → 采用/回退”的自动优化。优化器不能自行修改验收标准、授权边界或通过减少任务范围提高完成率。实验预算与用户当前任务分开。

参考：[Self-Harness](https://arxiv.org/abs/2606.09498)、[MemRL](https://arxiv.org/abs/2601.03192)、[Meta 专家纠错闭环](https://engineering.fb.com/2026/09/02/ml-applications/organizational-second-brain-ai-learns-from-experts/)。

## 8. 验收、迁移与限制

- 自动测试覆盖不同窗口（未知/小窗口/256K/1M）、不同输出字段、不同思考档位、RPM/TPM/ITPM/OTPM 与共享组。
- 至少连续三次压缩仍保留用户约束、来源、里程碑、文件路径、未完成任务与合法工具配对；摘要失败或取消不破坏旧记录。
- 测试停止、刷新、重启、切换模型后的同一任务恢复，不能重复已完成的副作用。
- 真实桌面隔离测试使用本地模拟上游与合成文件，验证 IPC、持久化、卡片与 UI；不自动使用用户密钥消耗付费额度。
- 评测结果区分算法/协议模拟通过与真实供应商模型效果；未经真实模型验证不得声称已获得跨模型完成率提升。
- 旧设置与 v2 执行记录可迁移，未知字段兼容；用户历史、附件、引用和注释继续保留。
- 构建类型检查、项目检查、自动回归、桌面/窄屏 UI 验证通过后再打包到独立版本目录，不关闭旧应用、不自动安装或发布。
