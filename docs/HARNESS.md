# 灯芯AI 2.2 执行与上下文设计

本版将“收到完整模型响应”和“可以向用户交付任务”分开处理。对话框中的任务引导可以关闭；取消、传输完整性、重复操作保护和明确执行证据的底线仍然保留。

## 实际故障依据

用户授权查看的本地记录中，截图所示修复日期任务只请求了一次模型：输入 81,194 tokens、输出 40 tokens，HTTP 200，明确收到 `finish_reason=stop`，但正文仅为“先核对真实状态，不做假设。”。当时没有工具执行、里程碑或验收条件，运行器直接记为完成。

审计范围自 2026-09-13 起的 43 个任务：22 个记为完成，其中 22 个均未定义验收条件，15 个没有工具、里程碑和验收记录。这些是观测缺口，不能据此声称 15 个任务全部失败。可识别的历史运行都使用流式请求，没有非流式对照，因此没有证据把问题归因于流式开关。

## 执行约束

任务引导按目标、必要澄清、相关代码阅读、最小改动、自查、相称测试和交付组织上下文。项目规范仍是项目规范，附件与历史摘要保留为材料。不会要求暴露私有思考过程，也不会把建议下一步自动变成新任务。

操作任务若只返回下一步计划，执行器最多自动续跑两次，然后明确暂停并保留检查点。没有成功操作记录的口头完成也会触发检查。已登记里程碑和验收条件继续经过原有交付门禁。`complete_task` 可以记录完成自查，证据编号必须确实存在且成功；模型自查与独立程序验证仍分别标注。这个检查不能证明任意复杂任务的语义正确性，用户结果反馈仍是独立依据。

## 分层上下文

稳定规范、当前目标与验收来源、近期操作和历史资料分开组织。自动整理使用带原文来源的摘要，只有已经成功整理过的历史用户资料才折叠为索引。当前目标和验收来源保持原文，所有被省略材料仍可通过 `read_context` / `read_tool_result` 分页恢复。整理目标是发送视图的软目标，不是上传文件上限或上游模型窗口的宣称。

文本附件上限 25 MiB、图片 20 MiB、一次附件合计 100 MiB。附件大小与模型上下文容量不同：大文件在支持读取的任务中按需查看，不自动假装已阅读所有内容。不支持材料读取的模型会给出明确限制。

## 临时子代理与本机连接

API 子代理由主模型在普通对话内像工具一样派发。用户先选择授权工作模型，默认只读，最多两路同时运行、单任务最多八次派发，不允许递归派发。每个子任务使用独立上下文和预算，稳定请求标识阻止重复发起；父任务等结果结束后再整合。重启后无法核实的子任务保留为结果待确认，不自动重发。

Codex、Claude Code 与 Kimi 沿用官方本机客户端。Claude Desktop 是 MCP 交接路径，模型和订阅登录由官方桌面应用管理；用户仍需在官方应用点击发送。交接从普通输入框发起，进度和结果回到同一轮；不要求必须配置 API 子代理。其交接当前支持最多 24,000 字符的文字上下文，图片需要在官方应用添加，超限不静默裁剪。

## 观测与 RSI

本版新增完成检查续跑次数、上下文折叠数和子代理结果状态，不把缺失的旧字段补成成功或零失败。分析页给出“未解决实例 → 脱敏排查 → 修复假设 → 同任务回归 → 检查正确性、耗时、用量 → 采用规则”的改进流程，不依据单次模型自评自动改写生产规范。

参考图中的上下文、工具、规则、验证与观测对应当前真实问题。模型路由和失败恢复沿用既有模块；本应用并不管理 GPU 推理集群，因此本次没有加入量化、vLLM 或负载均衡平台。这些不能解决此次提前交付和界面卡顿。

## 响应速度与重启

历史请求体只在打开用量详情时展开计算，输入草稿合并同步，流式显示按 120 ms 合并刷新。旧 Markdown 的缺省来源列表保持稳定，避免普通刷新重复解析和高亮。持久化优化保留原子提交、备份与失败保护，验证包含中断恢复。

专属 Chrome 配置目录跨重启复用，连接记录仅保存浏览器路径与端口；本机 AI 记住已验证的程序路径，启动后重新检测账号状态，不把上次在线伪装成当前在线。
