# AnyAI：交付验收、恢复体验与任务观测

状态：讨论稿已形成 1.3.0 实现；交付与验证进度见 [施工路线图](DELIVERY_RECOVERY_OBSERVABILITY_ROADMAP.md)。2026-09-13。

## 本轮取舍

优先实现交付验收与清晰恢复；同步建设本地任务统计。上下文压缩策略、模型接入策略的进一步调整，由真实交互任务和数据推动。本稿不预设这些策略存在已证实的质量问题，也不以自动结束率代替任务成功率。

用户先选择讨论设计，随后授权先实现交付验收和明确恢复，再按路线图完成观测与导出。本文件保留设计依据，实际完成情况以路线图为准。

## 交付验收

复杂任务保存用户要求、验收条件、对应产物/答案范围、证据及核验结果。执行里程碑描述过程，验收项描述结果，两者通过稳定 ID 对应。简单问答不强制建计划或增加模型调用。

- 要求从用户原始消息派生并保留来源；模型提出的拆解可自动展示，只有关键歧义才询问用户。
- 新的用户修正产生要求版本；保留替代关系，避免把原要求悄悄删除或把旧证据套到新要求。
- 验收状态：未检查、通过、未通过、无法自动核验。记录核验方法、证据引用、覆盖的条件、时间及要求版本。
- 工具成功只说明操作成功。文件存在、文件可解析、内容满足要求是不同检查；原始步骤 ID 或模型自述本身不能证明语义正确。
- 核验方法区分程序检查、模型复核、用户确认；模型复核不能标成独立的程序验证。程序检查只声称实际检查过的条件。
- 先用已有工具结果、结构化数据和读取操作检查；必要的模型复核计入预算。无法核验时明确展示，不为了获得“通过”无限重试。
- 最终交付呈现成果、要求覆盖情况、未核实项与访问入口。执行结束、验收通过、用户确认可用分别保存。

首批适合程序核验的范围由现有工具能力决定：文件存在及类型/解析、指定输出清单、结构化记录的必填项与数量一致性。课程日期完整性等需要可信源数据才能检查，不能仅凭生成文件断言完整。

## 暂停与恢复

暂停卡按任务结果组织：已完成内容和产物、具体阻塞点、已保存的下一步、推荐动作。保留日志展开入口。

| 原因 | 默认处理 | 用户可见信息 |
| --- | --- | --- |
| 暂时限流/短暂网络错误 | 在既有等待和预算范围内自动恢复 | 恢复时间或当前重试状态，可暂停 |
| 用户暂停 | 保留现场，等待用户继续 | 下一步及已保存成果 |
| 阶段预算耗尽 | 保存现场，等待继续或调整预算 | 本阶段消耗与剩余验收项 |
| 缺少输入/授权/能力 | 提出与阻塞直接相关的问题或动作 | 缺什么、影响哪项要求 |
| 外部操作结果不确定 | 优先执行已授权的只读核实 | 操作对象、已知状态、重试可能造成的重复影响 |
| 验收不通过 | 在预算内修复；无法修复则明确保留未完成项 | 哪项未通过、证据和可行下一步 |

核实结果不确定时不得推断成功或自动重复有副作用的操作。核实方法必须绑定具体工具和对象；没有可用核实能力时保留用户决定。继续沿用同一任务 ID，新建执行阶段，避免重复累计同一任务。

## 本地统计与观测

现有 RunState、requestStats、工具步骤和摘要记录可以复用，但需要独立的任务摘要索引，让完成后的任务也可统计。默认本地保存和聚合；不新增服务器或后台持续模型调用。外部汇总另行设计明确的用户选择。

### 首要约束：反映实际任务，避免误导

用户明确要求数据和信息能够反映实际情况，而不是令人混淆的数字。指标服务于解释任务结果和指导改进，不能仅为了产生仪表盘而收集。

- 每项分析先回答一个具体问题，再展示事实和证据。例如“哪些任务需要用户返工，返工发生在哪里”，而不是只展示请求量或工具调用数。
- 任务记录区分：用户提出的要求、实际产物、检查了哪些条件、未检查什么、用户后续反馈。任务目标/覆盖关系保存在本地；默认导出仅提供类别与覆盖状态，语义核对所需的具体内容由用户选择后补充。脱敏导致无法判断的部分必须说明。
- 正常结束、程序检查通过、模型认为完成、用户确认可用分别展示；用户暂停、修改需求、未反馈、仍在进行不能合并成失败。已知事实、估算、用户反馈和分析推断均带来源标签。
- 优先展示具体数量及状态分布；百分比同时展示分子、分母、筛选范围和观察期。可选反馈存在选择偏差，反馈覆盖率不能代替样本代表性。
- 不生成缺少可解释依据的综合分数、健康分或模型排行榜。跨版本/模型比较说明任务类型、复杂度、思考档位、工具和接口差异；任务组合不同或样本不足时不下优劣结论。
- 工具调用多、压缩次数多或消耗高都不自动代表质量差。只有与任务结果、重复失败、返工等证据结合才形成待验证假设；时间上先后发生不能直接判定因果。
- 聚合结果可定位到相关任务、阶段和允许查看的证据；导出保留这种关联。展示典型案例时同时说明选取规则，不只挑成功或失败案例。
- 缺失统计、程序中断后的观测缺口、估算用量及尚未结束的任务显式保留，不补零、不猜状态。展示任务开始与结束的时间范围，避免把迟到反馈错误计入另一个比较组。

默认报告按“实际交付和未解决事项 → 主要阻塞与返工 → 时间/用量花在何处 → 值得进一步核查的问题 → 数据限制”组织。每项问题关联样本数量和可追溯记录；没有足够证据时写“目前无法判断”，不自动建议调整策略。

最小模型：

- 任务：taskId、开始时间、要求版本、执行状态、验收状态、用户反馈。
- 阶段：attemptId、taskId、开始/结束时间、续跑来源、暂停原因、预算与等待时间。
- 事件：eventId、schemaVersion、taskId、attemptId、递增序号、时间、应用与运行时版本、事件类型及允许的字段。
- 分组：路由本地标识、模型、思考档位、能力信息是否已知、窗口/工作预算、是否发生压缩。切模型任务保留每阶段信息，不强行归因给最后模型。

建议事件：任务开始、要求修订、验收结果、暂停、恢复、操作核实、任务交付、用户反馈；请求、额度等待、压缩事件由已有记录补齐。按稳定事件 ID 去重，记录与恢复状态协调保存；重启恢复不重复制造“新任务”。

### 第一批指标

| 指标 | 口径与限制 |
| --- | --- |
| 执行结束率 | 正常结束任务 / 同一开始时间队列中的任务；同时展示仍在运行、暂停和观察期 |
| 验收通过率 | 必需验收项全部通过的任务 / 存在必需验收项且已结束验收的任务；同时展示未检查/无法核验比例及核验方法 |
| 用户确认可用率 | 确认可用 / 已反馈任务；同时展示反馈覆盖率，未反馈不计成功或失败 |
| 恢复效果 | 暂停任务中恢复、恢复后交付、恢复后验收通过分别计数；未继续不自动判失败 |
| 人工介入 | 缺输入、授权、故障处理、用户主动修改分别统计；授权不等于产品故障 |
| 成本与耗时 | 实际/估算 token 分列；模型等待、额度等待、工具耗时、用户离开时间分列；没有可靠价格不显示货币成本 |
| 压缩与质量线索 | 压缩次数、耗时、用量、校验失败、原文取回、后续纠正；相关性不是压缩导致错误的证明 |
| 接入问题 | 认证、参数不支持、限流、上下文超限、网络、工具失败分别计数，按样本数和任务复杂度解释 |

反馈入口保持轻量、可选：可用、部分可用、未解决；可选原因包括遗漏、内容错误、产物问题、执行中断。不用每次弹窗打断工作。用户后续纠正只能作为待判定线索，不能未经确认自动当成负面反馈。

### 保存与查看

- 统计事件采用字段白名单，不复制提示词、回答、思考内容、凭据、原始错误正文、附件正文或完整文件路径。需要排查时由本地 ID 关联已有任务日志。
- 本地可查看样本数、时间范围和版本，筛选到具体任务排查。支持清空统计和导出脱敏汇总；不把完整任务日志默认混入统计导出。
- 统计索引保留最近 90 天、最多 500 个任务，并受 4MB 容量限制；每任务保留最多 200 条事件、100 个执行阶段，2000 个明细去重标识后停止新增明细并继续更新汇总。裁剪明确记录，不限制原始任务工作记录。
- 当前设计中的“监控”是应用记录事件和本地聚合；没有创建定时唤醒或向外发送数据的监控任务。

### 导出供后续分析

导出是本轮必要功能，用户可把文件交给助手分析。入口提供时间范围、版本/模型筛选和导出内容预览，明确显示任务数量、缺失字段和将包含的信息。

默认导出“使用分析包”（ZIP），包含：

- `report.md`：可直接阅读的统计摘要、样本数、分母、观察期、反馈覆盖率、已知缺失及口径说明。
- `tasks.jsonl`：每个任务一行，包含执行/验收/反馈状态及按阶段的耗时、用量、暂停恢复、压缩、错误类别。使用导出专用标识，不包含任务标题、正文或完整接口地址。
- `events.jsonl`：用于还原阶段顺序的白名单事件；引用同一包内的任务与阶段标识。
- `manifest.json`：导出格式和指标口径版本、应用/运行时版本、筛选范围、时区、生成时间、脱敏规则、文件清单、事件覆盖范围及缺失计数。区分人工反馈、程序核验、模型复核和推断线索。

优先用本地确定性聚合生成报告，不额外消耗模型调用。路由使用包内别名；模型名可供分组，用户可以选择进一步隐藏。只声明具体移除了哪些字段，不宣称绝对匿名。

另设“指定任务排查包”，由用户明确选择任务后生成，增加恢复点、验收结果及核验方法、工具类别/状态、请求阶段和错误分类。若分析确实需要用户要求、答案、工具输入输出或错误正文，用户需另外选择相关片段并预览；默认不包含，凭据与思考内容始终排除。附件和整个工作目录不自动打包。

统计包支持寻找集中问题和选取排查样本；其本身无法判定答案是否正确或证明因果。需要内容核对时，后续再补充对应任务的脱敏材料。跨批次汇总按稳定的本地导出标识去重，重置导出标识后注明不可与旧包直接去重。

导出不是自动上传。生成后提供文件位置，用户自行决定分享；不需要额外部署云端统计系统。

## 验收与实施顺序

1. 确定任务/要求/核验/恢复/统计的数据口径与旧数据迁移；旧记录缺失字段显示未知，不回填虚构成功。
2. 实现结果验收和暂停恢复流程，同时记录上述事件；这两项共用任务状态。
3. 提供最小统计页与可选结果反馈；验证结束、暂停、重启、切模型和重复事件下的计数。
4. 以真实任务数据决定后续压缩与模型适配方向；每次改变策略保留版本，方便对照。

关键验证：证据存在但不满足条件不能通过；要求修订后旧验证不自动沿用；恢复不重复写入；未知外部状态不自动重试；正常结束不自动计作用户成功；缺反馈、缺 usage、旧版本记录不伪造统计；刷新重启不重复计数；导出不包含正文或凭据。

实施补充：反馈绑定用户评价时的执行阶段。续跑后旧反馈保留为历史反馈，不自动计作当前结果的确认。用户补充要求时，尚未派发的旧工具调用取消；已开始的操作先核实，可靠结果纳入记录后再重新规划。等待用户确认与额度等待、执行时间分别观测。
