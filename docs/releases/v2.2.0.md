# 2.2.0 — 本机协作、任务护栏与大附件

2.2.0 把 API 模型与本机订阅客户端的职责分开：API 路由负责兼容接口和连线检测，本机 AI 负责调用已登录的 Codex、Claude Code 等官方客户端。协作模型按需派发并展示进度，任务记录保留在本机。

任务执行增加可选的原生上下文管理与交付护栏：理解要求、必要时提问、按项目规范编辑、复核、测试和交付状态都能被程序记录；用户可以按模型能力关闭这套辅助流程。中断、流式结束或模型提前结束时保留现场，避免未完成任务被误判为完成。

附件限制统一为：单个文本或代码文件 25MB，单张图片 20MB，一次选择合计 100MB。超出时明确提示；原始附件保留在本机记录，长文本按需分页读取，避免把整份大文件静默放入每轮上下文。

大记录保存移到专用后台线程，避免阻塞主进程。已持久化的执行检查点不再重复写入普通会话，同时保留原始日志、原子替换和备份。57 MiB 合成数据写入测试中，主进程事件循环最大间隔为 26 ms；60 轮长对话按键响应 P95 为 16 ms。Chrome 专属登录资料与已验证的本机 AI 程序路径跨重启保留，在线状态仍实际检测。

发布流程由三个 Windows 批处理入口完成：安装、同步到 GitHub、推送版本标签并触发三平台构建。安装和同步均先执行回归测试与类型检查；正式 Release 只接受版本标签构建，避免从未标记或过期源码发布。

本地验证：284 项自动测试、类型检查、前端生产构建通过；真实 Electron 接口与标准 MCP 回传、普通对话交付和选择重载验证通过。隔离桌面实例完全退出再启动后，连接配置、所选 Claude Desktop 和对话结果仍保留。安装与发布入口已完成只检查模式验证。尚未安装、推送或发布；三平台安装包将在用户运行发布入口后由 GitHub Actions 构建与核验。本次没有替用户进行订阅账号登录。
