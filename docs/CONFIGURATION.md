# 配置说明

AnyAI 装完是一张白纸：**没有任何内置的 Key、端点、目录或权限**。
能力是一项一项配出来的，每配一项就多一类能做的事。这一页按「先配什么」的顺序讲完全部配置项。

最小可用：只配第 1 项，就能聊天。
想联网加第 2 项，想碰文件加第 3 项，其余都是可选的。

| # | 配置项 | 不配的后果 | 在哪 |
|---|---|---|---|
| 1 | [API 凭据](#1-api-凭据必填) | 什么都干不了 | 设置 → API 凭据 |
| 2 | [搜索源](#2-搜索源联网才要) | `web_search` 报错 | 设置 → 工具 → 搜索 |
| 3 | [工作目录](#3-工作目录碰文件才要) | 文件 / 命令行工具全部拒绝执行 | 设置 → 工具 → 工作目录 |
| 4 | [Chrome](#4-chrome控浏览器才要) | Chrome 类工具连不上 | 设置 → 工具 → Chrome |
| 5 | [GitHub Token](#5-github-token) | 只能读公开仓库，限流 60 次/小时 | 设置 → 工具 → GitHub |
| 6 | [Claude Code](#6-claude-code转包编码任务才要) | `claude_code` 工具找不到可执行文件 | 设置 → 工具 → Claude Code |
| 7 | [手机遥控](#7-手机遥控) | 手机端只能聊天，没有本地能力 | 设置 → 遥控 |
| 8 | [思考强度映射](#8-思考强度映射) | 用默认表，多数情况够用 | 设置 → 思考强度 |
| 9 | [生成参数](#9-生成参数) | 全部走服务端默认值 | 右侧配置面板 |
| 10 | [放行档位](#10-放行档位) | 默认逐步确认 | 输入框左下角 |

## 1. API 凭据（必填）

**设置 → API 凭据 → 添加**。一份凭据 = 一个 Base URL + 一个 API Key（+ 可选的额外请求头）。
可以存任意多份，随时在输入框左下角切换。

### Base URL

下拉里有几个预设，也可以直接填任何 **OpenAI 兼容** 的地址：

| 预设 | 说明 |
|---|---|
| `https://token.sensenova.cn/v1` | 商汤日日新 Token 端点，有免费额度 |
| `https://api.sensenova.cn/compatible-mode/v2` | 日日新官方 OpenAI 兼容模式 |
| `https://api.sensenova.cn/compatible-mode/v1` | 同上，老版本 |
| `https://api.moonshot.cn/v1` | Kimi / Moonshot，上下文缓存自动生效 |
| `https://api.deepseek.com/v1` | DeepSeek |

自建的聚合网关（one-api / new-api / LiteLLM / OpenRouter 之类）直接把它的地址填进来即可，
只要实现了 `POST /chat/completions` 和 `GET /models` 就能用。

地址会自动补 `https://` 并去掉结尾的 `/`，所以填 `api.example.com/v1` 也行。

### 测试连接 = 拉模型列表

点「测试连接」会打一次 `GET {base}/models`，把模型列表拉回来缓存住。

**模型列表是拉的，不是写死的**，上游上新模型不需要等这个项目更新。
端点没实现 `/models` 时会拉不到 —— 这不影响聊天，在右侧配置面板手动填模型 ID 即可，
模型选择器里搜不到的 ID 也能直接粘贴后回车加进去。

接聚合网关时模型常有几百上千个，选择器自带搜索，渲染上限 300 条。

### 额外请求头

某些网关要求带自定义头（比如分组、渠道路由）。在凭据编辑里按 `key: value` 逐行加，
会并进请求头一起发。

### 密钥存在哪

| 平台 | 加密方式 |
|---|---|
| Windows | DPAPI |
| macOS | 钥匙串 |
| Linux | libsecret |

密钥**不进渲染进程** —— 网络请求在 Electron 主进程里发，界面层拿不到明文。
系统不提供加密能力时（部分 Linux 桌面环境）会降级成明文存储并在界面上明确警告，
那种情况下请把数据文件当敏感文件对待。

其余配置和对话记录明文存在同一个文件里：

| 平台 | 路径 |
|---|---|
| Windows | `%APPDATA%\AnyAI\store.json` |
| macOS | `~/Library/Application Support/AnyAI/store.json` |
| Linux | `~/.config/AnyAI/store.json` |

### 模型和凭据是**会话级**的

输入框左下角那个按钮同时管模型和凭据，改的只是**当前这个会话**的绑定。

会话创建时会把当时的凭据钉下来，这是故意的 —— 否则翻旧对话时模型和端点会跟着全局设置漂走。
代价是旧会话可能绑在一份你已经不用的凭据上（表现为「模型列表跟刚测试连接时对不上」），
左下角随时能改。

## 2. 搜索源（联网才要）

**设置 → 工具 → 搜索**，三选一：

| provider | 拿 Key 的地方 | 免费额度 | 返回什么 |
|---|---|---|---|
| **Tavily**（默认） | app.tavily.com | 1000 次/月 | 专为 LLM 做的，直接给清洗过的正文 |
| **Brave** | brave.com/search/api | 2000 次/月 | 独立索引，只给标题 + 摘要 |
| **SearXNG** | 自建实例，填地址 | 自己的机器 | 聚合各家结果 |

选 Brave 的话，模型拿到的只有摘要，要正文得再调一次 `fetch_url`，等于多一轮。
选 SearXNG 记得在实例的 `settings.yml` 里打开 json 输出格式：

```yaml
search:
  formats:
    - html
    - json
```

不开的话请求会被实例直接 403。

搜索结果会自动编号成可点击的来源，出现在答案下方。

## 3. 工作目录（碰文件才要）

**设置 → 工具 → 工作目录 → 添加目录**。可以加多个。

**一个都不加 = 所有文件类工具和 `run_command` 直接拒绝执行。** 这是故意的默认值，
不是没做完 —— 不该有任何应用默认拿到你整块磁盘。

路径守卫的做法是先 `realpath` 解引用再跟白名单比对，所以用符号链接指到目录外面绕不过去。

**别把整个家目录加进来。** 加什么就等于授权什么，白名单里的东西没有第二道边界。
推荐的粒度是「这次要做的那个项目文件夹」。

受这一项管的工具：`list_dir` `read_file` `search_files` `read_document`
`write_file` `edit_file` `write_document` `run_command` `claude_code`。

## 4. Chrome（控浏览器才要）

**设置 → 工具 → Chrome → 点「启动可控制的 Chrome」**。只有这一步，不用自己敲命令行。

### 为什么不能控你日常那个 Chrome

**Chrome 136 起，`--remote-debugging-port` 在默认用户数据目录下会被直接忽略**，
这是 Google 为了堵住「拿调试端口偷 cookie」做的安全变更。

所以网上那些让你加 `--user-data-dir="...\User Data"` 指回默认配置的教程，在 136 之后
**既不工作、原理上也是在拆掉一道防护**。这个项目不会那么做，也不会去读你默认配置里的 cookie ——
那段代码跟窃取 cookie 的恶意软件在做的是同一件事。

### 这个按钮实际做的事

用一份**独立的持久化配置目录**（应用数据目录下的 `chrome-profile`）拉起 Chrome：

- 第一次要在那个窗口里登录一遍你要用的网站
- 登录状态会一直留着，不用每次重登
- 完全不碰你日常那份 Chrome 配置，也不需要退出日常 Chrome

找不到 Chrome 会自动退回用 Edge，行为一致（同样走 CDP）。

调试端口默认 `9222`，可以在同一页改（端口被占时改一个）。

### 点了没反应

最常见的原因是**你已经开着同一个浏览器的普通窗口**：已有实例在跑时，新进程只会把启动请求
转给旧实例然后自己退出，调试端口根本不会监听。把那个浏览器**完全退干净**（托盘里也要退）再点一次。

### 需要装扩展吗

不需要。CDP 是 Chrome 自带的协议，扩展给不了「读任意标签页 + 点任意元素 + 执行 JS」这种权限，
反而更受限。

## 5. GitHub Token

**设置 → 工具 → GitHub**。不填也能用，只是：

- 只能读公开仓库
- 限流 60 次/小时（填了 token 是 5000 次/小时）
- 装私有仓库里的技能会 404

填一个 fine-grained token，只给 `Contents: Read` 就够读和装技能；
要让模型开 issue / 提 PR 才需要更大的范围。Token 跟 API Key 一样走系统加密存储。

---

## 6. Claude Code（转包编码任务才要）

**设置 → 工具 → Claude Code**。本机装了 `claude` CLI 并登录过就能用，找不到就填绝对路径。

默认附加参数：

```
--permission-mode acceptEdits
```

**这个不能省。** headless 模式（`claude -p`）下不给权限模式，它遇到需要授权的操作会卡住
等一个永远不会来的回答，直到超时。想更放得开可以改成 `--dangerously-skip-permissions`，
但那意味着它改什么都不问你。

超时默认 10 分钟（`claudeTimeoutMs: 600000`）。编译型项目跑测试容易超，可以调大。

`claude_code` 的 cwd 必须落在工作目录白名单内。

## 7. 手机遥控

Android 端自己没有文件系统和命令行权限，本地能力靠电脑转发。

**电脑端**：设置 → 遥控 → 启动服务。记下显示的地址（局域网 IP + 端口，默认 `8719`）和令牌。
**手机端**：设置 → 遥控 → 把地址和令牌填进去 → 测试连通。

连上之后手机端的工具调用会发到电脑执行，确认弹窗在**手机上**弹。

> **只在内网用。不要把这个端口做端口转发暴露到公网。**
> 校验只有一道 Bearer token，而它背后就是你电脑的命令行。

## 8. 思考强度映射

同一件事（「多想一会儿」）各家 API 的字段完全不同：

| 厂商 | 实际字段 |
|---|---|
| OpenAI 系 | `reasoning_effort: "low" \| "medium" \| "high"` |
| Anthropic 系 | `thinking: { type: "enabled", budget_tokens: 12288 }` |
| 通义 / 智谱 | `enable_thinking: true` + `thinking_budget: 12288` |
| DeepSeek reasoner | 没有开关，一直思考 |

所以对外只给**一档五级刻度**，在**输入框右下角**选，切模型不用重学：

```
不下发  →  低  →  中  →  高  →  超高  →  拉满
```

翻译交给 **设置 → 思考强度** 里那张映射表。**按顺序匹配模型 ID，第一条命中的生效。**

### 第一条必须是「模型名自带强度」

默认表的第一行是一条正则，匹配这种模型 ID：

```
dva/claude-5-fable-high     gpt-5-minimal     qwen3-thinking     o4-mini-high
```

聚合网关常把强度烤进路由名里，后缀本身就是那条路由的思考预算。客户端再叠一个字段上去，
轻则被忽略，重则 400。

**这一条必须排在所有厂商规则前面** —— 否则 `dva/claude-5-fable-high` 会先被「Claude」
那条规则抓走，然后被塞进一个 `thinking` 对象。

### 哪几条没实测

标了「推测」的（Kimi、日日新）是按厂商惯例填的，**没有逐个验证**。
报 400 就去改那一行，不用改代码。

想完全手动接管：在右侧配置面板把「下发方式」从「自动」改掉。

## 9. 生成参数

右侧配置面板，`temperature` / `top_p` / `max_tokens` / `top_k` / `min_p` / 重复惩罚等等。

**没勾选的参数根本不会出现在请求体里**，走服务端默认值。这样某个模型不认识 `top_k` 或 `min_p`
时不会直接 400 —— 这是刻意的设计，不是懒。

其它几个同页的开关：

| 项 | 默认 | 说明 |
|---|---|---|
| 流式响应 | 开 | 关掉就是等整包返回 |
| 携带历史条数 | 全部 | **改成有限值会破坏上下文缓存前缀**，见下 |
| 工具轮次上限 | 可调，上限 100 | 一次提问最多几轮工具调用 |
| 启用哪些工具 | 新会话默认只开只读的 | 逐个勾 |

想加新参数：在 `src/lib/paramSchema.ts` 的 `PARAM_DEFS` 里补一行，
UI 表单和下发逻辑会自动跟上，不用改别处。

### 上下文缓存（Kimi / Moonshot / DeepSeek）

现在是**全自动的** —— 没有接口要调、没有 header 要发、没有缓存对象要建。
超过 256 token 的请求，重复的前缀自动命中，命中部分按更低价格计费。

客户端唯一能做的是**别把前缀搞乱**。为此做了两件事：

1. **工具清单下发前排序** —— 否则你在面板上勾一下工具，`tools` 序列化的顺序就变了，
   整段前缀跟着失配，缓存永远命中不了
2. 只往历史后面追加，不改写前面的内容

有两个操作会主动破坏前缀：

- 把「携带历史条数」从「全部」改成有限值（会从头部截断，每轮前缀都不同）
- 超长对话触发的旧工具输出压缩（保留最近的全文，更早的压成一句摘要，总预算 12 万字符）

命中了多少 token 显示在每条回答下面（`缓存命中 N tok`）。
不同厂商的缓存字段名（`cached_tokens` / `prompt_cache_hit_tokens` / `prompt_tokens_details.cached_tokens`）
都已归一化。

## 10. 放行档位

输入框左下角那个按钮，**每个会话各自记住，对话中途随时能切**：

| 档位 | 行为 |
|---|---|
| 🔒 逐步确认（默认） | 每个会改变状态的操作都先问 |
| ◐ 自动批准编辑 | 写文件、Chrome 操作直接放行；跑命令和调 Claude Code 仍然问 |
| ⚡ 全部放行 | 一句不问，包括在你电脑上执行任意命令 |

确认弹窗支持键盘：**Enter 批准，← 或 Esc 拒绝**。
拒绝不会中断对话 —— 模型会收到「用户拒绝了」，然后换个办法继续。

**这是模型误操作时唯一的实质性防线。** 详见 [SECURITY.md](../SECURITY.md)。

自动跑的定时任务建议设成「自动批准编辑」或更松，否则它会停在确认弹窗前等你回来点。

### 哪些工具要确认

| 工具 | 组 | 需要电脑 | 执行前确认 |
|---|---|---|---|
| `web_search` `fetch_url` | 联网 | | |
| `list_dir` `read_file` `search_files` `read_document` | 本地文件 | ✓ | |
| `write_file` `edit_file` `write_document` | 本地文件 | ✓ | ✓ |
| `run_command` | 命令行 | ✓ | ✓ |
| `chrome_tabs` `chrome_read_page` | Chrome | ✓ | |
| `chrome_navigate` | Chrome | ✓ | |
| `chrome_click` `chrome_eval` | Chrome | ✓ | ✓ |
| `github_search` | GitHub | | |
| `github_api` | GitHub | | ✓ |
| `claude_code` | Agent | ✓ | ✓ |
| `project_memory_read` `project_doc_read` `skill_list` | 项目与技能 | | |
| `project_memory_write` | 项目与技能 | | |
| `project_doc_write` `skill_write` | 项目与技能 | | ✓ |

加新工具 = 在 `src/lib/tools/registry.ts` 加一条声明 + 在 `electron/tools/index.cjs` 加一个执行器，两处。

## 会话级授权：目录 / 管理员 / 屏幕

默认状态下模型只能在工作目录里活动、不能提权、看不见屏幕。这三样它可以**申请**：

| scope | 申请后能做什么 | 默认 |
|---|---|---|
| `path` | 多一个可读写目录 | 无 |
| `admin` | `run_command` 带 `elevated` 以管理员身份跑（Windows） | 无 |
| `screen` | 截屏 + 鼠标 + 键盘 | 无 |

弹窗会显示它申请的范围、它自己写的理由、以及同意之后的风险。同意之后：

- **只在本次会话有效**，关掉应用就没了，不落盘
- 输入框上方出现常驻提示条，随时可以「全部撤销」
- 对应的工具会被自动勾上 —— 否则同意了也用不了
- **提权命令和权限申请永远单独弹确认，连「全部放行」档位都不例外**

屏幕控制只实现了 Windows（Electron 的 desktopCapturer 截图 + PowerShell 调 user32.dll
注入输入，零原生依赖）。其他平台直接拒绝，不假装能用。

提权走 `Start-Process -Verb RunAs`，**会弹系统 UAC 由你亲手点**。这里没有也不会有绕过 UAC 的实现。

风险详见 [SECURITY.md](../SECURITY.md)，尤其是屏幕控制那一节 —— 截屏会把当时屏幕上的
一切发给模型服务商。

## 模型健康度与自动重试

接了聚合网关之后，模型列表里几百条路由不是每条都活着。1.0.0 起：

**自动重试。** 开启后，临时限流、断网与超时在恢复预算内等待重试；5xx 和不完整响应另外受重试次数限制。
优先遵守上游恢复时间，未知时使用退避。中断的临时文本会回退到已保存的轮次边界，避免重复拼接；
已完成工具不会因此重做。等待可停止，默认单次自动恢复上限 15 分钟。

**自动记账。** 一次对话撞上「服务端确定性崩溃」（报错里带环境变量、沙箱路径、
堆栈这类服务端实现细节）或「模型不存在」，这个 ID 就被记一笔。攒够 2 分从默认
列表里移出，折叠进「有问题的模型」。确定性错误一次记 2 分，可能是瞬时的记 1 分 ——
所以偶尔抖一下的模型不会被误伤，真坏的一次就沉下去。

成功一次清零。限流、超时、鉴权失败**不算模型的锅**，不记分。

**只看聊天模型。** 聚合网关会把 Stable Diffusion 的 checkpoint、embedding、rerank、
语音模型全列进 `/models`，它们打不通 `/chat/completions`。选择器里默认按 ID 和 owner
的形态把这些折叠掉，开关在模型列表上方，点一下就能看到全部。判断刻意保守：宁可漏判
也不误判，把能用的聊天模型藏起来比多留几个噪音更糟。

**批量体检。** 模型选择器底部那个按钮，给每个模型发一个最小请求
（`max_tokens: 16`，不带工具、不带思考强度），只测「这条路由通不通」。
并发压到 2，撞到限流全体暂停再重试那一个 —— 体检本身把额度打爆的话，
一批好模型会被记成「限流」，那比不测还糟。

几百个模型跑完要几分钟，随时能停，已测的结果保留。

手动干预：列表里每行悬停出现 ✕ 可以手动隐藏一个模型；「有问题的模型」里的 ↩
把它放回正常列表。手动决定不会被体检推翻。

## 项目 / 技能 / 定时任务

这三项没有「配置」的概念，是用的时候现建的，但有几处行为值得先知道。

### 项目

侧栏底部 📁 新建；对话顶栏的下拉可以把**已经开始的对话**随时移进移出项目。

一个项目 = 一组对话 + 一份共享上下文：

| 带什么 | 怎么生效 |
|---|---|
| 项目规范 | 拼进这个项目里每一轮的 system prompt |
| 项目记忆 | 同上；模型用 `project_memory_write` 往里追加跨对话的结论 |
| 文档 | **只把目录拼进去**，正文让模型用 `project_doc_read` 按需取 |
| 常用提示词 | 输入框空着时以小胶囊出现，点一下填进去 |
| 默认模型 / 凭据 | 在这个项目里新开对话时自动套上 |

文档为什么不全量注入：一个项目攒几万字很正常，每轮都塞进去等于每轮重付一次钱。

### 技能

侧栏底部 ⚡。在输入框打 `/名字` 唤起（↑↓ 选，Enter 确认），作为额外的 system 消息注入这一轮。

**技能是提示词，不是可执行代码** —— 装一个技能不会在你机器上跑任何东西，所以不需要沙箱。
格式与 Anthropic 的 SKILL.md 一致（YAML frontmatter 给 name / description，正文是指令），
GitHub 上现成的技能仓库能直接装：

```
owner/repo
owner/repo/skills/some-skill
https://github.com/owner/repo/tree/main/skills
```

会找这几个位置的 SKILL.md：给定路径本身、路径下一层的每个目录、仓库根的 `skills/` 和
`.claude/skills/`。不做深递归，免得把整个仓库爬一遍。私有仓库要先配 GitHub token。

也可以直接跟模型说「把刚才那套流程存成技能」，它会用 `skill_write` 自己写一个。

### 定时任务

侧栏底部 ⏰。到点自动发一条消息给模型，工具照常能用。
四种排程：每隔 N 分钟 / 每天 / 每周几 / cron（标准 5 段，自己解析的，支持 `* , - /`）。

> **调度器跑在应用里，应用关着就不会触发。**
> 补偿是「错过补跑」：下次打开应用时把漏掉的补上一次。

要做到关掉窗口也能跑，得把整个 Agent 循环搬进主进程再实现一遍，而且工具确认弹窗没人点照样会卡住
—— 不值这个复杂度。

## 界面

| 操作 | 怎么做 |
|---|---|
| 收放侧栏 | `Ctrl+B`，或侧栏左上角的 ⇤ / 顶栏的 ⇥ |
| 调栏宽 | 拖栏之间的把手，**双击恢复默认** |
| 发送 | Enter（可在设置里改成 Ctrl+Enter） |
| 粘贴图片 | 输入框里直接 `Ctrl+V`（截图工具、网页右键复制图片都行） |
| 钉选对话 | 侧栏每条右边的 📍 |
| 分叉对话 | 侧栏的 ⑂ 复制整个上下文；每条回答右上角的 ⑂ 只复制到那一步 |
| 搜对话 | 超过 4 条时侧栏出现搜索框，标题和正文都搜 |

主题（跟随系统 / 亮 / 暗）和字号在 设置 → 外观。

## 疑难

### 1.2：自动上下文与任务进度

输入框旁的圆圈显示本次请求的估计输入占用；未知窗口显示问号，不伪造百分比。
展开可看窗口来源、输出预留（含思考）、工作预算、内容明细、摘要次数和分钟额度。
空闲时是发送前草稿估算，运行时是实际准备发送的请求；实际计费取上游 usage。

“配置 → 当前路由能力”可填写模型窗口、输出上限、RPM、TPM、ITPM、OTPM。
留空保持未知，模型列表元数据和明确的上游报告会参与计算。填写更低限制会作为硬约束。
共享同一账户/项目额度的凭据可填相同“共享额度组”；更换网关地址不会沿用原地址的窗口记录。
高级项可指定输出上限字段、当前路由各思考档位的实际写法，以及缓存输入是否计入输入额度。

自动模式先从窗口中扣除输出预留与安全空间，工作目标最高 96,000 输入 token；
这是本版本的成本与整理频率默认值，不是模型质量阈值。可切换手动模式填写更大的工作预算，
仍需满足真实窗口、单次额度与阶段 token 预算。旧版自定义上下文预算保留为手动模式。

先缩减工具结果和大型附件；需要时使用当前模型生成结构化摘要，摘要调用会计入阶段用量。
“允许语义摘要”可关闭，此时保留本地缩减与原文检索。原始材料没有删除，模型可分页取回文本或原图。
过大的纯用户指令不会被擅自改写；必要内容仍放不下会说明原因并保留进度。

复杂任务可按需建立里程碑。完成项划掉，展开“完成证据”可读对应执行结果。
简单问答无需计划。仍有待办不会因模型说“完成”就自动结束；受阻或预算不足时暂停。
已有里程碑会继续保留并核验，关闭自动创建不会抹去未完成任务。

本轮支持现有 Chat Completions 兼容接口，不能保证所有网关支持同样的思考字段，也不能保证零 429。
供应商原生协议、原生压缩与自动自我优化留在后续版本。

### 1.1：长任务、引用回复和文件记录

配置面板可设置上下文模式、每阶段 token 预算、最长时间，以及自动恢复等待上限。
1.2 起默认自动适配；窗口未知时使用约 24,000 输入 token 的工作预算（不是模型上限）。
阶段默认 300,000 累计 token、60 分钟、单次自动恢复 15 分钟。
token 数在发送前为估算，收到 usage 后使用实际用量；每次“接着跑”开启新的阶段预算。
图片按每张 2,048 token 的通用预留值估算，不把 Base64 传输编码当文字；不同模型的实际图片用量仍以上游 usage 为准。
TPM/RPM 留 0 表示未知，程序会采用上游明确报告的额度，也可手动填写。
单次请求超过整分钟额度时先缩小可检索的上下文；必要输入或所选输出仍放不下才暂停。
等待不能解决单次超额，Retry-After 不会被截成短间隔反复重试。

“停止”会暂停本轮和排队消息，保留已经完成的工具步骤。重启后点击“接着跑”从断点恢复。
已经完成的原生工具调用直接复用结果；若写文件、命令或网页操作在中断前已开始而完成状态未知，
会要求核实后选择跳过或允许重试。应用关闭期间不会继续执行任务。
连续重复工具错误、阶段轮次/预算耗尽或最终回答失败都显示本地进度，不会被当成任务完成。

选中同一条回答或问题里的文字，选区旁会出现“回复”“注释”浮动菜单。点击“回复”后，输入框会保存引用原文与来源，
默认只发送所选段落和本次问题，同时保留系统提示与项目规范；取消勾选可携带当前会话历史。
引用发送后可点击来源跳回原消息。引用内容作为材料发送，不能替代系统指令。
点击“注释”可给选中段落保存个人笔记，在原消息旁显示，支持编辑、删除和重启恢复；这些注释不会自动发送给模型。

每轮底部显示输入/输出文件卡片，包含名称、大小与路径；桌面端支持“打开”“在文件夹中显示”“另存为”。
ICS 可以直接预览，答案里的完整 ICS 代码块也可点击“保存文件”。
工具写出的文件会核实实际路径；通过命令生成的文件应填 `run_command.output_files`，或调用 `register_outputs`。
模型仅在正文提及路径不等于文件已经交付。文件已移动、删除或未获目录访问权限时会显示核实错误。
路径核实只证明文件存在，不验证日历事件内容是否准确。

“请求记录/自动排查”使用发生失败时的具体请求，保留轮次、尝试、响应正文与可用响应头。
不会用后来生成的汇总替代失败现场；上游不给详细原因时，诊断会保留不确定性。

**「模型列表只有几个，明明网关有几百个」**
这个会话钉的是一份旧凭据。输入框左下角换成新的那份。

**报错看不懂 / 不知道该怎么办**
1.0.0 之后每个失败都会给出「怎么回事 + 现在该做什么」，原文折叠在卡片底部。
如果卡片说的方向不对，把原文贴进 issue。

**同一个模型老是 500**
那条路由在上游是坏的，客户端改什么都没用。模型选择器里点「批量体检」，
一次把这个网关上所有不能用的路由筛出来，它们会被折叠进「有问题的模型」，
不再占正常列表的位置。

**思考强度一选就 400**
多半是模型名自带强度又被叠了字段。检查 设置 → 思考强度 里「模型名自带强度」是不是还在第一行，
或者把这个模型的强度设成「不下发」。

**文件工具全部报「没有配置工作目录」**
就是字面意思，见 [第 3 项](#3-工作目录碰文件才要)。

**Chrome 工具连不上**
先点「启动可控制的 Chrome」，并确认日常 Chrome 已经完全退出。见 [第 4 项](#4-chrome控浏览器才要)。

**图片发过去 400**
纯文本模型收到图片会直接报错，换一个多模态模型
（日日新里 `sensenova-6.7-flash-lite` 是多模态的）。

**PDF 读出来是空的**
扫描件没有文字层，需要先 OCR。工具会明确这么告诉你，而不是吐一堆空白。

**改名之后配置没了**
不该发生 —— 启动时会自动从 `%APPDATA%\SenseNova Chat` 迁移。
没迁过来的话把那个目录下的 `store.json` 手工拷到 `%APPDATA%\AnyAI\` 即可，
密钥不受影响（safeStorage 的密钥按操作系统用户算，跟应用名无关）。

## 交付检查、继续任务与导出记录（1.3）

复杂任务会按用户要求建立交付检查清单。回答中的“交付验收”显示每项检查的方法、依据和限制。程序检查通过只说明所列条件已检查；模型复核、无法核验和未建清单都会明确标注。验收失败时会继续尝试修复，在当前预算内无法完成则保留现场。

暂停卡中的“补充信息后继续”可以补充缺少资料或修正要求。未开始的旧操作会取消，已经开始的操作先核实；结果不确定时需要明确决定，不会自动重复外部提交。

侧栏底部的“任务记录与分析”可以查看状态分布、当前阶段反馈和具体任务。选择时间、模型或版本后，点击“生成导出预览”，检查内容，再“保存导出包”。默认使用分析包包含 report.md、tasks.jsonl、events.jsonl、manifest.json，可交给助手分析。选择某一任务“排查”可单独导出；正文和工具结果片段默认不包含，需要另外勾选并检查预览。

结果反馈是可选的本地记录。续跑后，先前反馈会显示为较早阶段的评价。统计保留期限和容量见面板说明；“清空统计与反馈”保留原任务和文件，重新开始记录。应用不会自动上传分析包。
