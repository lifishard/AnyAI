# 上下文与模型接力（1.3.1）

灯芯AI 的核心使用方式是在同一窗口让不同模型接力完成任务。任务记录属于应用和用户，不依赖某个模型会话的隐式记忆。接力必须带上当前要求、事实与不确定性、成功证据、失败原因和下一步。

## 两种接续路径

- 暂停任务：选择新模型，再点“接着跑”或“补充信息后继续”。沿用原任务 ID、执行游标、要求、验收、工作记录和语义总结；新阶段按新模型窗口及输出预留重新计算预算。
- 同窗口后续提问：构造历史交接材料，包含总结、里程碑、验收状态、最近工具证据及文件索引；用户更正保留原文。完整记录通过 read_context 读取，完整工具输出通过 read_tool_result 读取。旧工具证据不重复计入本轮执行统计，本轮有独立交付清单。

执行中切换选择器只影响下一次启动。需要立即交接时先暂停，再选择模型继续。切换本身不额外调用模型生成总结：复用已有语义总结，没有总结时保留原始工作记录，并生成基于记录的交接说明。

## 核心约束

1. 用户原文和最新更正优先于历史模型总结。交接材料是历史数据，不是新的系统指令或授权。
2. 旧版“携带历史条数”不再裁剪执行上下文，避免把原始目标或总结切掉。必要上下文装不进新窗口时明确暂停。
3. 语义压缩按完整工具批次进行；原始记录不被覆盖，来源可查。总结不会仅因换模型失效。
4. 已成功操作先读证据，结果不确定的操作仍须核实，换模型不会自动重试。
5. 连续三次相同操作返回同样结果后，再次重复会记为未执行并暂停；工具调用和结果仍配对完整。新阶段可换方法继续，不自动重启预算。
6. 禁用检索工具时，不用无法读取的引用代替原文，也不新建语义压缩。缺少必要证据应明确说明；工具及目录授权按当前设置生效。
7. 仅讨论引用、编辑或删除来源时，不重新导入已排除的历史记录。交接不传递独立的隐藏思考字段。

## 可观察性

“接力上下文”显示前后模型、接续模式、保留记录数量及准备/发送状态。这些是上下文传递事实，不证明模型理解正确。

分析包的 context_handoff 事件记录阶段、模式、状态、是否换模型、记录数量和总结可用性，不写入正文、完整路径或来源任务内部 ID。旧工具仅作为检索证据，不变成本轮新执行次数。

## 验证

- 60 项自动检查通过，涵盖 historyLimit=1 时跨模型接续、总结及原文读取、用户更正、引用/删除/修改隔离、重载及连续重复暂停。
- 隔离原生桌面、本地模拟接口：A 写一次文件 → B 刷新后承接总结并读取 A 原文 → 暂停切回 A 继续，共 5 次请求。窗口 262144 → 32768 → 262144；任务 ID、统计与接力事件持久化，文件修改时间不变。
- 桌面 1440×1050、窄屏 430×932：接力信息、补充续跑、验收、反馈、导出及清理通过。

上述验证的是请求内容和执行行为，尚未进行真实供应商的模型质量评测。总结仍可能遗漏语义，模型仍可能误读；需结合真实交付、用户反馈和分析包继续评估。
